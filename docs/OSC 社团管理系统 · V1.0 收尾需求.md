## 一、背景与定位

### 1.1 为什么是"V1.0 收尾"而不是"V1.1"

V1.0 的定位是**首个可对外发布的版本**。代码写完 ≠ 版本完成——当前代码功能齐备，但 UI/UX 层面存在明显不足，达不到"能拿出手"的标准。

因此本需求**不引入新能力**，只做三件事：
1. 修 UI/UX 层面的问题（菜单、登录页、响应式、风格）
2. 补 V1.0 遗留的 3 项待办
3. 产出上线自测清单

### 1.2 版本节奏共识

| 版本     | 触发条件                                             |
| :------- | :--------------------------------------------------- |
| **V1.0** | 本需求完成 + 社长自测通过 + 全流程演练通过           |
| **V1.1** | 上线后按真实用户反馈做小修小补                       |
| **V2.0** | 能力层/架构级变更（数字资产库、整站 i18n、飞书集成） |

**不刻意凑版本号**——V1.x 用几个算几个，够格了直接跳 V2.0。

### 1.3 本需求范围（Must）

| 分组       | 项                                                           |
| :--------- | :----------------------------------------------------------- |
| 视觉规范   | Vercel 风格 + 三层配色体系                                   |
| 登录页     | Logo / 去连通性卡 / 居中 + 背景图                            |
| 主页与导航 | 一二级菜单 / 公告合并 / 账号区上移 / 图标化 / 设备适配       |
| A 池收尾   | 报名页 Logo + 活动照片轮播 / 对象存储孤儿清理 / 纳新设置权限 |
| 文档产出   | 上线自测清单                                                 |

**明确不做**（推后）：
- 整站 i18n → V2.0
- 反馈回复功能 → V1.1
- 日志落盘 → V1.1
- 自动化测试 → 伴生任务
- 数字资产库 → V2.0

## 二、视觉规范（Vercel 风格 + 三层配色）

### 2.1 三层配色体系

> **✅ Logo 真实色值已实测（2026-09-28）**：把 `web/public/Logo ZH.svg` 内嵌的 PNG（726×726）解出来采样，
> 主要色分布为 —— **`#3557F4` 占 13.1%**（主体文字亮蓝，最大单一色）、**`#908AFF` 占 9.0%**（装饰几何的青紫渐变），
> 与本文「主体文字亮蓝 + 装饰几何青紫渐变」的描述**完全吻合**。
> ⚠️ 因此 **品牌主色建议直接用实测值 `#3557F4`**（原稿的 `#2B4EFF` 与之相差约 4%，肉眼几乎不可辨，但既然有精确值就用精确的）。
> 「青蓝动效色」原稿定 `#00D4FF`，**Logo 里没有这个色** —— 它是**有意加的"科技感点缀色"**（不来自 Logo），保留。

Logo 实际使用两套颜色（主体文字亮蓝 + 装饰几何青紫渐变）。为避免 UI 与 Logo 抢焦点，采用**三层分工**：

| 层级            | 色值                          | 用途                                              | 面积占比 |
| :-------------- | :---------------------------- | :------------------------------------------------ | :------- |
| **品牌主色**    | **`#3557F4`**（实测自 Logo 主体文字；原稿 `#2B4EFF`） | 菜单当前项、主按钮、链接、Tab 激活态              | ≈10%     |
| **强调/动效色** | `#00D4FF`（青蓝）             | hover 微动效、loading、进度条、图表高亮、渐变点缀 | ≤5%      |
| **中性灰阶**    | Vercel 灰阶                   | 背景、文字、边框、次要按钮                        | ≈85%     |

**原则**：
- 用户第一眼看到 **Logo**（品牌识别）
- 第二眼看到 **品牌蓝的当前菜单/主按钮**（功能定位）
- 第三眼才注意到 **青蓝的细微动效**（科技感）
- 三层不打架

### 2.2 圆角（三档，不许混用）

> **现状（已核对）**：`index.scss` 里只有**一个** `--brand-radius: 8px`（且已映射给 Vant `--van-radius-md`）。
> 下表三档 = **目标**，落地需新增变量并逐处替换（详见 §2.7 的提醒）。

| 档位        | 值         | 用途               |
| :---------- | :--------- | :----------------- |
| 常规控件    | **6px**    | 按钮、输入框、标签 |
| 弹窗 / 菜单 | **12px**   | 模态框、下拉菜单   |
| 全屏容器    | **16px**   | 页面级大块面       |
| 药丸 / 头像 | **9999px** | 标签、头像         |

### 2.3 间距（4px 基准）

- **4px 基准**：4, 8, 12, 16...
- **三步节奏**：组内 8px / 组间 16px / 板块间 32-40px

### 2.4 动效（克制，能不动就不动）

| 场景         | 动效                     | 时长  |
| :----------- | :----------------------- | :---- |
| 菜单项 hover | 左侧 2px 青蓝竖条滑入    | 150ms |
| 按钮 hover   | 背景从品牌蓝渐变到青蓝   | 200ms |
| 页面切换     | 内容区淡入（透明度 0→1） | 100ms |
| 数据加载     | 顶部 2px 青蓝进度条      | —     |
| 图表 hover   | 数据点放大 + 青蓝光晕    | 150ms |

**明确不做**：背景粒子、视差滚动、loading 动画超过 1 秒。

### 2.5 阴影

- **非常弱**，主要靠背景色调与边框建立层级
- 阴影只用于气泡、悬浮卡片和对话框

### 2.6 字体

- 使用系统字体栈（中文场景没必要引英文字体）
- **所有标题的 letter-spacing 都是负值**，越大越紧

### 2.7 配色落点

- 主色集中在 `src/styles/index.scss` 的 CSS 变量，映射 `--el-color-primary` 与 `--van-primary-color`
  （✅ **已核对**：该文件确实存在且已做这两条映射，落点正确）
- 青蓝只出现在动效与图表高亮，不进常规组件

> **⚠️ 只改 `--el-color-primary` 不够（重要技术提醒）** —— Element Plus 组件的 **hover / border / disabled / 浅底** 用的是
> `--el-color-primary-light-{3,5,7,8,9}` 与 `--el-color-primary-dark-2` 这一组派生变量。
> 当前 `index.scss` **只覆盖了主色**，所以换色后这些态**仍是 EP 默认蓝**，会出现「按钮主色变了、hover 还是旧蓝」的割裂。
> **建议**：在 `index.scss` 里**一并显式给出**这 7 个派生值（可以手算或先用在线工具生成一组），
> 或改用 SCSS 的 `map.merge` 覆盖 EP 主题变量。**这条不写进 T21 方案，T21 一定会返工。**

> **另外两处换色时要同步改的地方**（原稿未提）：
> 1. `index.html` 的 `<meta name="theme-color" content="#409eff" />`（手机浏览器地址栏配色）
> 2. `web/src/styles/index.scss` 的 `--brand-radius` 目前是**单一值 `8px`**，而 §2.2 要求三档（6/12/16）
>    → 需新增变量（如 `--radius-control/-popup/-surface`）并逐处替换，同时 `--van-radius-md` 要跟着映射。

**问题**：现在左侧菜单是纯文字，与页面标题容易混淆，不易快速定位。

**改法**：
- 每个菜单项配一个图标（Element Plus 内置图标库）
- 折叠态只显示图标
- 移动端底部 tabbar 同样图标化

### 4.5 响应式与设备适配

**问题描述（已按代码实况修正）**：
- ⚠️ **不存在「折叠为图标态」这个状态** —— `useIsMobile()` 只按 **`<768px` 单断点**判断（`composables/useIsMobile.js`），
  `<768` 时 `AppShell` 把整个左侧菜单**换成**底部 tabbar + 一个抽屉（`el-drawer`），**没有中间的图标折叠态**。
- 社长的真实体感「缩窗口后无法唤出菜单」的成因：`<768` 后左侧菜单整体消失，唤醒入口只剩页头里一个**文字按钮「菜单」**
  （`<el-button text>菜单</el-button>`），太不显眼 → 看起来像"没有菜单了"。
- 底部菜单与左侧菜单「重复出现」：**实况是互斥的**（`v-if="isMobile"` / `v-if="!isMobile"` 二选一），不会同屏重复。
  若曾看到同屏，需复现确认（可能是断点抖动）。

**改法（三断点）**：

| 断点       | 形态                                         |
| :--------- | :------------------------------------------- |
| ≥1024px    | 左侧菜单完整展开（图标 + 文字）              |
| 768~1024px | 左侧菜单折叠为图标态（悬停展开）**← 新增的能力** |
| <768px     | **底部 tabbar（图标 + 文字）**，隐藏左侧菜单 |

**折叠按钮改为标准三横杠图标**（`Menu` 图标），不用文字。

**移动端底部 tabbar**：按菜单 order 取前 3~4 项 + "更多"抽屉（现状 `tabbarItems = items.slice(0, 3)`）。
