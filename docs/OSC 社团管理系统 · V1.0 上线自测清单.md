### 执行顺序说明

**为什么 T21（视觉规范）排最前**：

- 它是全站基础设施——配色、圆角、动效定下来后，后续所有 UI 改动一次到位
- 如果先改菜单、再定视觉，菜单要改两遍

**为什么 T22 在 T23 前**：

- 菜单结构（分组、图标、账号区）先定，响应式才有明确的对象去适配

**为什么 T28 叫"上线自测"而不是"V1.0 收尾自测"**：

- 它是 V1.0 上线前**最后一道闸门**——你走完这遍，通过就打 tag 发布

**为什么 T30 只做"准备"不做"执行"**：

- 实际部署是发布动作，属于版本发布流程，不必列为开发任务
- 但检查表、备份、部署方案要在 T29 里全部就绪
