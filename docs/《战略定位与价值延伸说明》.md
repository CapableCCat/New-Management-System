# 《战略定位与价值延伸说明》

> **文档性质**：战略与定位定稿文档，承接《旧系统技术审视与重构建议》（技术基线，已归档）与《最终PRD》（业务定稿）。
> **核心议题**：系统与飞书的差异化定位、数据资产价值、输入方案、多维度价值延伸（毕设/软著/招标/个人成长）。
> **状态**：✅ 已定稿。本文档用于答辩、软著申报、汇报、对外讲解"为什么做、价值在哪"。


## 0. TL;DR（战略速览）

1. **定位明确**：系统是社团的**数字档案馆**，而非官网（展示）或飞书（沟通）。三者形成"展示—沟通—数据"的闭环铁三角。
2. **飞书不是对手，是互补品**：飞书管"当下聊天"，系统管"历史资产与流程状态"。系统不做IM，通过飞书机器人Webhook推送通知，变成飞书背后的"能力插件"。
3. **数据价值是核心护城河**：系统回答飞书回答不了的"关联性问题"（谁借了资产、报名过程卡在哪、三年荣誉一键查）。
4. **输入方案已定稿**：不做飞书API自动拉取（需付费+权限复杂），改用"飞书导出Excel→系统导入"半自动模式 + "快记面板"轻量录入。
5. **一套代码，三重收割**：同一套核心工程，可分别包装为**高质量毕设**（加推荐算法）、**软著申报**（加模块命名）、**学校招标/横向推广**（加外置配置与Docker交付）。
6. **架构预留三大锚点**：字典化、配置外置、容器化——V1.0 功能克制，但为未来铺路。


## 1. 核心战略定位：与官网、飞书构成"铁三角"

| 系统/平台           | 核心定位             | 服务对象                           | 关键特征                                       | 时间属性    |
| :------------------ | :------------------- | :--------------------------------- | :--------------------------------------------- | :---------- |
| **社团官网**        | 数字化门面 / 展示窗  | 校外访客、潜在新生、合作方         | 品牌形象、社团介绍、往期活动相册、外链         | 静态/回顾   |
| **飞书（IM+协作）** | 内部沟通与敏捷协作   | 社团全体成员（日常）               | 即时聊天、视频会议、云文档协同、审批流         | 实时/进行时 |
| **OSC 管理系统**    | 数据资产库与流程引擎 | 管理层、纳新对象、需查询历史的成员 | 成员档案、流程状态、资产台账、荣誉墙、统计报表 | 动态/可追溯 |

**一句话定性**：
> **飞书负责"喊人开会"，OSC负责"会议纪要落地为档案"；官网负责"把成果讲出去"，OSC负责"把成果存下来并有据可查"。**


## 2. 系统与飞书的最终定位矩阵

经与社团运营同学沟通确认：飞书在"日常运营功能"上对社团完全够用，系统**不与飞书竞争功能**。

| 平台         | 核心定位       | 服务对象                  | 数据流向         | 用户操作频率                  |
| :----------- | :------------- | :------------------------ | :--------------- | :---------------------------- |
| **飞书**     | 日常协作工作台 | 全体成员                  | 数据**产生**于此 | 每天                          |
| **OSC 系统** | 社团数字档案馆 | 管理层 + 需查询历史的成员 | 数据**归档**于此 | 每学期1~2次（导入）+ 按需查询 |
| **社团官网** | 对外展示门面   | 访客、新生                | 数据**呈现**于此 | 浏览者为主                    |

**一句话定调**：
> **飞书是"笔和纸"，社团用它写字；OSC系统是"档案柜"，把写好的纸按年份整理好，十年后还能找到。**


## 3. 系统数据的核心价值

系统获取的数据不是冰冷字段，而是回答以下**飞书无法回答**的高价值问题：

### 3.1 纳新场景（过程观测，体验优化）
| 飞书现状（痛点）                                   | OSC系统价值（解法）                                     |
| :------------------------------------------------- | :------------------------------------------------------ |
| 只看到群里"我报名了"的刷屏，不知道总共多少人填了表 | 系统记录**报名过程数据**：扫码→提交→通过→激活，按日归档 |
| 干部A说"我审了"，干部B说"我也审了"，重复/漏审严重  | 系统记录**审核人 + 审核时间 + 拒绝原因**                |
| 不知道多少新生卡在"填写中途退出"                   | 可统计**表单放弃情况**，辅助优化报名表                  |

### 3.2 资产管理场景（解决"东西去哪儿了"）
| 飞书现状（痛点）                  | OSC系统价值（解法）                           |
| :-------------------------------- | :-------------------------------------------- |
| "树莓派谁拿了？"→翻群聊找"我拿了" | **资产领用表**：资产编号+借用人+借用/归还时间 |
| 设备借出后无人跟进                | 支持**超时未归还自动提醒**（飞书Webhook催还） |
| 发票/保修卡照片散落个人云盘       | **资产附件上传**，统一归档，换届不丢失        |

### 3.3 荣誉与传承场景（解决"凭据去哪儿了"）
| 飞书现状（痛点）                     | OSC系统价值（解法）                              |
| :----------------------------------- | :----------------------------------------------- |
| 2023年"十佳社团"奖状在上届社长朋友圈 | **荣誉墙模块**：按年份归档+奖状图片+参与成员名单 |
| 新部长申请"优秀社团"需找往年材料     | 一键导出**社团年度成果包**（荣誉+活动+成员列表） |

### 3.4 活动运营场景（沉淀经验，避免重复造轮子）
| 飞书现状（痛点）                        | OSC系统价值（解法）                          |
| :-------------------------------------- | :------------------------------------------- |
| 办过5次技术沙龙，每次重新建群、重新统计 | **活动模板**：一键复制往期活动配置，快速发起 |
| 参与度只能靠"来了多少人"估算            | **签到数据 + 活动后问卷反馈**，输出活动ROI   |

**结论**：系统数据的本质是**"把社团运营经验数据化、可查询、可传承"**——这是飞书的多维表格和聊天记录永远做不到的。


## 4. 与飞书的优劣势矩阵（正式版）

| 维度             | OSC 管理系统（优势 ✅）                                     | 飞书（劣势 ❌ / 差异）                          | OSC 的劣势（正视 ⚠️）     |
| :--------------- | :--------------------------------------------------------- | :--------------------------------------------- | :----------------------- |
| **数据关联性**   | ✅ 强关联结构：成员←部门←资产←活动←荣誉，支持复杂联表查询   | ❌ 数据孤岛：表单、文档、日历互不打通           | 初期数据量少，优势不明显 |
| **业务流程定制** | ✅ 深度定制：纳新状态机、审核拒绝必填原因等逻辑写死在业务层 | ❌ 需复杂配置，难以强约束                       | 开发迭代依赖技术人员     |
| **权限精细度**   | ✅ 行/列级权限：部长只看本部门，敏感列分级可见              | ❌ 文档级权限，难以实现"同一张表不同人看不同列" | 权限设计需花心思         |
| **历史档案沉淀** | ✅ 永久归档：离社账号冻结，数据永久保留                     | ❌ 聊天记录被刷走、多维表版本混乱               | 需承担数据存储与备份成本 |
| **移动端体验**   | ❌ 完败（H5 vs 原生App）                                    | ✅ 极致原生体验                                 | **不挑战飞书移动端**     |
| **消息实时性**   | ❌ 无内置IM、无推送                                         | ✅ 强推送，必达                                 | **不做IM，仅做业务通知** |
| **稳定性/SLA**   | ❌ 个人服务器 vs 商业集群                                   | ✅ 99.9%可用性                                  | 需部署公网，提前压测     |
| **学习成本**     | ❌ 需培训干部使用                                           | ✅ 全员熟悉                                     | 需准备操作手册+线下培训  |

**整合策略**：
> **系统不与飞书竞争IM，而是通过飞书机器人Webhook将审核结果、活动提醒、资产超期等业务通知推送至飞书群，让飞书成为系统的通知渠道，系统成为飞书的数据后台。**


## 5. 输入方案定稿：半自动导入 + 快记

**背景**：自动调用飞书API拉取通讯录/多维表格需要飞书企业版（付费）+复杂权限审批，且数据映射易出错，V1.0 不可行。

**最终决策**：采用以下三种输入方式，均**不依赖飞书API**：

| 输入方式             | 操作路径                                           | 适用场景                           | 频率             |
| :------------------- | :------------------------------------------------- | :--------------------------------- | :--------------- |
| **Excel批量导入**    | 飞书导出Excel → 系统后台拖拽上传                   | 纳新后导入新成员、换届后更新通讯录 | 每学期1~2次      |
| **"快记"面板**       | 极简录入浮窗：标题+分类（荣誉/资产/活动）+附件上传 | 干部即时记录"社团拿奖了""买了设备" | 按需，每次10秒   |
| **公告联动**（V1.5） | 发布公告时勾选"同时记录为活动/荣誉"                | 减少重复录入                       | 每次发公告时顺便 |

**输入原则**：
> **系统只接收"整理过的数据包"和"关键节点的快照"，绝不强制运营同学进行日常数据录入。** 系统像一台"拍立得"，只在有重要成果（荣誉/大活动/换届）时记录瞬间；而不是像监控摄像头，24小时不停录入日常琐事。


## 6. 飞书集成范围定稿

| 集成项                       | 是否做          | 理由                                             |
| :--------------------------- | :-------------- | :----------------------------------------------- |
| **飞书OAuth2.0免登**         | ✅ 做（Stretch） | 免费版支持；解决移动端登录体验；标准协议         |
| **飞书API拉取通讯录/多维表** | ❌ 不做          | 需付费版本+复杂权限审批+数据映射成本高           |
| **飞书机器人Webhook推送**    | ✅ 做（V1.5）    | 简单HTTP调用，免费；让飞书成为通知渠道           |
| **飞书原生小程序**           | ❌ 不做          | 需重写前端，维护成本高；V1.0 先做 H5 嵌入飞书工作台 |

**移动端最终方案**：
- 前端构建**响应式H5页面**（Vue 3 + 移动组件库或响应式适配）
- 飞书开发者后台创建"企业自建应用" → 配置移动端主页地址指向H5
- 前端调用飞书 JSAPI 获取免登 code → 后端换取 user_id 完成免登（具体 API 以飞书最新开发者文档为准）
- 管理后台（PC端）保留浏览器访问 + 账密登录（备选通道）

### 7.3 面向学校招标 / 横向推广（校本化交付）

如果未来向学校信息中心、其他学院或社团推广，他们最看重"能不能改、好不好装、安不安全"。为此，在 V1.0 开发阶段进行**三项技术预埋**：

| 技术预埋项                   | 具体实现                                                     | 未来价值                                        |
| :--------------------------- | :----------------------------------------------------------- | :---------------------------------------------- |
| **字典全量外置**             | 部门、职位、状态、学院、兴趣标签等均存于`sys_dict`表，提供后台字典管理界面 | 其它学院/社团接入时，后台改配置即可，无需改代码 |
| **配置全量环境变量化**       | DB/Redis/MinIO的密码、IP、端口改为`${MYSQL_HOST:localhost}`形式注入，提供`.env.example`模板 | 满足等保安全要求；杜绝密码泄露进代码仓库        |
| **Docker Compose一键部署包** | 编写`docker-compose.yml`（MySQL+Redis+MinIO+Backend+Nginx），一条命令拉起全栈 | 向学校汇报时现场演示"5分钟部署一套新系统"       |

## 8. 最终价值宣言

> **对个人**：它是一份可以写进简历、申请软著、通过毕辩的完整作品。

> **对学校**：它是一套符合"数据自主可控"要求的私有化运营平台雏形。
